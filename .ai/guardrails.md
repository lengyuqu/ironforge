# IronForge Agent 生命周期护栏（Permission Boundary Rules）

> **本文件定义 AI Agent 在 IronForge 项目中执行操作时的权限边界。**
> 所有 AI 编程助手（Claude Code / Codex / Cursor / Qoder / WorkBuddy 等）在执行任何变更操作前，
> **必须**检查本文件中的护栏规则，对高风险操作触发确认流程或拦截。

> **状态**：维护中 ｜ **可信度**：确认 ｜ **来源**：仓库代码 / 文档 / 运行结果 ｜ **最后更新**：2026-08-14

---

## 护栏等级定义

| 等级 | 标识 | 含义 | Agent 行为 |
|------|------|------|-----------|
| 🔴 **BLOCK** | 禁止执行 | 操作不可逆或影响生产安全，Agent 不得自动执行 | 拒绝执行，向用户说明原因并建议人工操作 |
| 🟠 **CONFIRM** | 需确认 | 操作有风险但可逆，需用户明确确认后方可执行 | 暂停执行，列出影响范围，等待用户确认 |
| 🟡 **WARN** | 需警告 | 操作有潜在副作用，需告知用户风险 | 告知风险后继续，除非用户要求逐条确认 |
| 🟢 **ALLOW** | 允许 | 常规开发操作，无特殊风险 | 正常执行 |

---

## 高风险操作清单

### 1. 数据库迁移（Database Migration）

| 操作 | 等级 | 说明 |
|------|------|------|
| 新增迁移文件（`rg-db/src/migrations/`） | 🟠 CONFIRM | 必须确认表名与实体 `table_name` 一致（单复数踩坑） |
| 执行 `ironforge migrate` 命令 | 🟠 CONFIRM | 对现有数据库执行 DDL 变更，需确认目标 DB 路径 |
| `ALTER TABLE` / `DROP TABLE` / `DROP COLUMN` | 🔴 BLOCK | 不可逆结构变更，Agent 不得自动执行 |
| `RENAME TABLE` / `RENAME COLUMN` | 🟠 CONFIRM | 可能破坏现有查询，需确认所有引用已更新 |
| 修改现有迁移文件内容 | 🔴 BLOCK | 已执行的迁移不可修改，只能新增 |
| 新增 `ADD COLUMN`（带默认值） | 🟡 WARN | 需确认幂等守卫（`has_column()`） |

**确认流程**：
```
⚠️ 数据库迁移确认
━━━━━━━━━━━━━━━━━━
操作: [具体操作描述]
目标: [数据库路径/URL]
影响: [受影响的表/列]
回滚: [是否可回滚，如何回滚]
━━━━━━━━━━━━━━━━━━
请确认是否继续？(y/n)
```

### 2. 部署操作（Deployment）

| 操作 | 等级 | 说明 |
|------|------|------|
| `docker compose up/down/restart` | 🟠 CONFIRM | 影响运行中的服务实例 |
| 修改 `deploy/docker-compose*.yml` | 🟡 WARN | 影响部署配置，需确认变更意图 |
| 修改 `Dockerfile` | 🟡 WARN | 影响构建产物，需确认变更合理性 |
| 修改 `deploy/.env*` 中的密钥/凭据 | 🔴 BLOCK | 涉及生产密钥，Agent 不得修改 |
| 执行 `docker push` / 镜像发布 | 🔴 BLOCK | 发布到外部注册表，不可撤回 |
| 修改 CI/CD 工作流（`.github/workflows/`） | 🟠 CONFIRM | 影响自动化流水线行为 |
| 执行 `deploy/start-observability.sh` | 🟠 CONFIRM | 启动监控栈，占用系统资源 |

**确认流程**：
```
⚠️ 部署操作确认
━━━━━━━━━━━━━━━━━━
操作: [具体命令/文件变更]
环境: [开发/测试/生产]
影响: [受影响的服务/端口/资源]
回滚: [回滚方案]
━━━━━━━━━━━━━━━━━━
请确认是否继续？(y/n)
```

### 3. 删除操作（Deletion）

| 操作 | 等级 | 说明 |
|------|------|------|
| 删除源代码文件（`crates/` 下 `.rs` 文件） | 🟠 CONFIRM | 需确认无其他模块引用 |
| 删除测试文件 | 🟡 WARN | 降低测试覆盖率 |
| 删除迁移文件 | 🔴 BLOCK | 已执行迁移不可删除 |
| 删除数据库文件（`*.db` / `*.db-wal` / `*.db-shm`） | 🔴 BLOCK | 数据不可恢复 |
| 删除 `repos/` 下的裸仓库目录 | 🔴 BLOCK | Git 数据不可恢复 |
| 删除配置文件（`ironforge.toml` / `.env*`） | 🟠 CONFIRM | 影响服务启动 |
| `git push --force` / `git reset --hard` | 🔴 BLOCK | 不可逆 Git 操作 |
| `git branch -D` / `git tag -d` | 🟠 CONFIRM | 可能丢失未合并工作 |
| 批量删除（`rm -rf`、`find -delete`） | 🔴 BLOCK | 任何批量删除操作一律禁止 |
| 删除文档文件（`docs/` / `ironforge-docs/`） | 🟡 WARN | 需确认文档已过时 |

**确认流程**：
```
⚠️ 删除操作确认
━━━━━━━━━━━━━━━━━━
操作: [删除目标]
原因: [为什么需要删除]
影响: [依赖此文件/数据的模块]
替代: [是否有替代方案（如归档到 archive/）]
━━━━━━━━━━━━━━━━━━
请确认是否继续？(y/n)
```

### 4. 安全与认证（Security & Auth）

| 操作 | 等级 | 说明 |
|------|------|------|
| 修改认证逻辑（`rg-core/src/auth/`） | 🟠 CONFIRM | 影响系统安全边界 |
| 修改 JWT secret / 加密密钥配置 | 🔴 BLOCK | 导致所有现有 token 失效 |
| 修改权限校验逻辑（`can_read`/`can_write`） | 🟠 CONFIRM | 可能导致权限绕过 |
| 添加/修改密码哈希参数 | 🟠 CONFIRM | 影响现有用户登录 |
| 修改 CORS / Rate Limit 配置 | 🟡 WARN | 影响安全策略 |
| 引入新的外部依赖（`Cargo.toml`） | 🟡 WARN | 需确认依赖安全性 |

> **凭据策略**：Agent 不得把账号密码、token、secret、API key、私钥原文写入任何文档、代码或提交信息；文档只记录环境变量名或凭据存放位置。

### 5. Git 协议核心（Git Protocol Core）

| 操作 | 等级 | 说明 |
|------|------|------|
| 修改 `rg-git/src/protocol/` 下的协议实现 | 🟠 CONFIRM | 影响所有 Git 客户端兼容性 |
| 修改 pkt-line / sideband 编解码 | 🟠 CONFIRM | 协议底层，错误会导致所有操作失败 |
| 修改 `rg-ssh/` SSH 认证流程 | 🟠 CONFIRM | 影响 SSH 访问安全 |
| 修改分支保护逻辑 | 🟠 CONFIRM | 影响代码合并安全门禁 |

### 6. 数据完整性（Data Integrity）

| 操作 | 等级 | 说明 |
|------|------|------|
| 修改 `rg-db/src/entities/` 实体定义 | 🟡 WARN | 需确认与迁移和 ops 一致 |
| 修改 `rg-db/src/ops/` CRUD 操作 | 🟡 WARN | 影响数据读写正确性 |
| 修改 `AppState` 结构 | 🟠 CONFIRM | 需同步更新测试构造器 |
| 修改 BlobStorage / LFS 存储路径逻辑 | 🟠 CONFIRM | 可能导致已有文件不可访问 |

## 确认流程规范

### 触发条件

当 Agent 识别到即将执行的操作匹配上述任何 🟠 CONFIRM 或 🔴 BLOCK 规则时：

1. **🔴 BLOCK**：Agent 必须**立即停止**，输出拦截原因，建议用户手动执行或提供替代方案
2. **🟠 CONFIRM**：Agent 必须**暂停执行**，输出确认模板，等待用户明确回复"确认"/"继续"/"yes"后方可继续
3. **🟡 WARN**：Agent 输出风险提示后可继续，但需在操作总结中标注已执行的风险操作

### 确认输出格式

```
🚨 Agent 护栏触发
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
等级: [🔴 BLOCK / 🟠 CONFIRM / 🟡 WARN]
类别: [数据库迁移 / 部署 / 删除 / 安全 / Git协议 / 数据完整性]
操作: [具体操作描述]
文件: [涉及的文件路径]
影响: [影响范围说明]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[对于 CONFIRM]: 请回复"确认"继续执行，或"取消"放弃。
[对于 BLOCK]: 此操作已被拦截，请人工执行。建议方案：[替代建议]
```

### 批量操作规则

- 如果一个任务涉及多个高风险操作，Agent 应**逐一确认**，不得批量跳过
- 如果用户明确表示"本次会话所有同类操作均确认"，Agent 可跳过后续同类确认，但需在最终总结中列出所有已执行的高风险操作

Agent 在完成包含高风险操作的任务后，必须在总结中附加以下信息：

```
📋 高风险操作记录
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. [操作描述] — [等级] — [已确认/已拦截]
2. [操作描述] — [等级] — [已确认/已拦截]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 豁免条件

以下情况可豁免确认流程：

1. **用户明确指令**：用户在当前消息中明确要求执行该操作（如"直接执行迁移"）
2. **测试环境**：操作目标明确为临时测试路径（如 `/tmp/`）且用户已知晓
3. **CI 上下文**：在 CI/CD 流水线中由自动化脚本触发的操作（非 Agent 主动执行）

---

## 护栏维护

- 本文件由项目负责人维护，AI Agent 不得自行修改护栏规则
- 新增高风险操作类型时，应同步更新本文件
- 护栏规则的变更需经人工审核，不得通过 AI 自动提交
