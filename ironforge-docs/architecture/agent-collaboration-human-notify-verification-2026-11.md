# 协作：问题与阻塞到达人的通知出口（验证记录，2026-11-06）

> **状态**：已实现，仅 SQLite 验证 ｜ **可信度**：确认（附运行证据）｜ **来源**：仓库代码 + 本次运行

## 做了什么

此前 agent 提出的问题只有打开协作页才看得到。现在**创建问题**的那一刻，会给有权回答的人写一条站内通知（现有的铃铛、未读数和 WebSocket 推送直接复用）：

- `repo_writers`：仓库所有者、写/管理协作者、组织的所有者/管理员及对本仓有写权限的团队成员，**发送时逐人用当前权限重判**（绕过 30 秒权限缓存）；单个问题最多通知 50 人（`MAX_RECIPIENTS_PER_QUESTION`），铃铛封顶，"等待你处理"列表不受影响。
- `user`：只通知那个用户，且只在其当前可读该仓库时；不存在的用户 id、读不了该仓的用户**什么都不发**（否则会泄露标题、确认 id）。
- `session`：不发人的通知（会话已有持久 notice，且会话只是标签）。
- 幂等重放不重复通知；并发同键只有创建成功的那一个调用发通知。
- 通知是创建**提交之后**的尽力而为：失败只记日志，不使问题创建失败。
- 通知标题是问题标题（客户端所写，原样当文本）；问题正文**不**复制进通知。

读取侧：`GET /notifications` 新增 `repo`（`owner/name`，仅当仓库存在且调用者当前可读）。`collab_*` 类通知在读者失去访问权后，标题显示为 "(no longer available)"，正文与 `repo` 置空。

前端：导航栏通知旁的未读徽标（登录后拉取并每 60 秒刷新，通知页加载时同步）、通知项的"打开"链接指向 `/{owner}/{repo}/collaboration`、`collab_question` 的类型标签与提示语在前端本地化（服务端只存标题与英文正文）。

不需要迁移：`notifications` 表未改；链接目标由 `repo_id` 推出。

## 任务被声明为阻塞（`collab_task_blocked`）

- **通知谁**：只通知该任务**负责会话所属的账号**（同账号多 agent 下即"你的 agent 卡住了"），**不**通知仓库里的其他写入者；负责会话属于另一账号时通知那个账号。无负责会话的任务没有收件人，不通知。
- **何时**：仅当更新**真的把状态改成 `blocked`**（上一状态不是 `blocked`）。上一状态取自更新前对同一任务的读取；写入本身对 `expected_version` 做比较并设置，读到的版本不一致时写入会失败，所以读到的状态就是被替换的状态。`blocked → blocked`（改别的字段）不通知。
- **去重**：同一用户对同一任务已有**未读**的同类通知时不再新增，来回切状态不会刷屏；读过之后下一次被阻塞再通知。
- 通知标题是任务标题（客户端所写，纯文本），正文为固定英文句；前端用自己的措辞包装（"任务被声明为阻塞"）。状态是声明，不是核实。仍是创建/更新**提交之后**的尽力而为。
- 其他状态（`waiting` 等）不通知。

## 未覆盖

- 仅 SQLite；PostgreSQL/MySQL 未跑（逻辑只用既有表与既有 ops，无新 SQL）。
- 没有邮件、没有 webhook 事件：通知不出本实例。
- 只有"问题"和"任务被声明为阻塞"两种事件。`waiting`、交接、问题被答复、崩溃或会话过期等**没有**人类通知；阻塞通知也不看"阻塞了多久"（那是升级提醒的事，且只发给会话）。
- 通知不去重于"同一问题反复被重新提出"：每个新创建的问题各一条。
- 徽标靠轮询（60 秒）和通知页同步，没有跨页的实时推送。
- 没有逐用户的通知偏好或静音。
- 多实例部署下，WebSocket 推送只到连在**处理该请求的实例**上的客户端；落库的通知仍可被轮询取到。
