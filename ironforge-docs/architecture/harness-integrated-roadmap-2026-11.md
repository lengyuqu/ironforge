# Harness 原生化：Codex 建议、Claude 方案对照与整合路线

> 状态：Proposed，待评审，非实施完成声明。
> 日期：2026-11-04。
> 来源：本次 Codex 设计评审、[现有 harness 草案](harness-native-design-2026-11.md)（本文称 Claude 方案）、当前工作区代码静态核对。
> 可信度：代码存在性为确认；新增设计与优先级为建议；测试执行、集成、运行和发布均待验证。
> 范围：服务端能力、客户端契约与验收计划。本次仅新增文档和索引，不执行迁移、修改业务实现或发布。

## 1. 整合结论

IronForge 的核心场景是：多个不同的 Agent 使用同一个用户账号操作同一仓库时，仍能知道彼此是谁、正在做什么、需要什么协助，以及如何可靠交接。平台还应让 harness 回答：当前读取的是哪个版本、刚才的操作执行到了哪里、哪些验证足以支持下一步动作。

保留 Claude 方案的接口基础：预算化读取、CI 反馈、受限身份、统一权限检查、dry-run、并发控制、幂等、事件和共享客户端。Codex 补充快照一致性、提交绑定的验证证据、持久化操作恢复、可失效计划、轻量交接与真实任务评测。

核心交付顺序：核对在制实现与建立基线 → 同账号 Agent 的会话身份与协作最小闭环，同时推进快照和 CI 证据 → 受限写入与可靠操作 → 客户端闭环 → 历史重放。协作消息和交接的首版不等待完整写工具、事件系统或历史 PR 导出。

## 4. 补充契约

### 4.1 快照与上下文版本

代码读取返回解析后的完整 commit SHA，后续 tree、file、diff 均可用 SHA 读取。现有 `commit` 字段沿用，不另造同义字段。PR context 返回 `base_sha`、`head_sha`、元数据版本及各节来源；Git SHA 不能代表评论、批准和策略的版本。

分页游标绑定仓库、commit、路径、过滤条件和排序；后续请求不能在活动分支上重新计算偏移。快照不可读取时显式报错，不静默切换到最新分支。搜索返回 `indexed_commit` 与 freshness 状态；索引构建应原子发布其内容和版本，不能把旧索引标为新 SHA。默认分支索引与请求快照不同，则明确提示不匹配，不伪称任意 ref 搜索。

预算接口同时报告实际字节或字符数、估算方式、截断节和下一页；token 估计不当作精确值。

### 4.2 提交绑定的验证证据

验证记录最小字段：仓库、被测 commit、base/head 或合并候选 SHA、pipeline/job/attempt、工作流内容摘要、环境或镜像摘要、检查名称、状态、时间、日志/制品定位与摘要、证据来源。

区分可信 runner 结果与 Agent 自述；上传“测试通过”的文本不能满足受保护分支检查。跳过、取消、未执行不能归为通过。head 变化使旧检查不能满足新 head 的门禁；base 变化使依赖目标分支的集成证据过期，但不必否定与 base 无关的单提交检查。重跑以独立 attempt 留存，明确当前适用结果的选择规则。

首期复用现有 pipeline/job 数据，先建立关联与查询契约，再评估是否新增独立证据表，避免重复存储整段日志。合并队列验证实际候选 SHA，并在移动目标 ref 前重新检查适用证据和期望 ref。

### 4.3 operation、幂等与部分成功

首批覆盖提交、合并、入队和重跑。服务端接受操作后返回持久 `operation_id`，查询状态包括 `accepted`、`running`、`succeeded`、`failed`、`needs_attention`；查询受当前仓库权限约束。短操作可同步完成并直接返回最终结果。

记录请求摘要、主体、目标仓库/ref、期望 SHA、结果 SHA/资源 ID、后续投递状态。幂等键的命名空间至少包含主体、仓库、动作和 key，并核对规范化请求摘要。并发同键通过唯一约束或等效原子机制只接纳一次；换 token 恢复的范围由稳定主体身份与授权决定，不能只依赖旧 token ID。

Git ref、数据库与外部投递不能假设具有一个共同事务。先持久化意图、通过 CAS 更新 ref、持久化结果，并用恢复任务对账；在关键边界故障后，根据 ref 和操作标识判断效果，禁止盲目再次生成提交或覆盖他人更新。webhook 等后续动作有独立重试状态。无法确定时标记 `needs_attention`，不能伪报失败后诱导重复执行。

### 4.4 无副作用预览与持久计划

普通 `dry_run` 只计算效果，不创建计划记录、operation、审计、通知或队列项。需要用户审阅后执行时，显式创建持久计划：包含 `plan_id`、规范化请求摘要、`expected_refs`、相关元数据/批准版本、`policy_version`、`expires_at` 与 effects。

执行时重新鉴权，校验全部前提；不一致返回 `PLAN_STALE` 并说明变化项。计划 ID 不能充当权限或人类批准。已消费计划通过幂等操作返回既有结果；过期和变更均不自动放宽约束。新建分支使用“不存在”前提，不能用空 SHA 绕过 CAS。

### 4.5 恢复类型与事件

错误新增 `recovery.kind`：`retry_after`、`refresh_required`、`replan_required`、`approval_required`、`not_retryable`，并可带等待时间和状态定位信息。`REF_ADVANCED` 需要重新读取和验证；超时导致结果不明时先查 operation，不直接原样重发。

事件采用至少一次交付，消费者按稳定 `event_id` 去重。DB 业务状态与 outbox 在同事务提交；事件分发可重复但不能漏掉已提交业务事件。Git 更新通过 operation 对账桥接。游标应遵循已发布的稳定顺序，不能直接假设自增 ID 的分配顺序等于事务提交顺序。并发晚提交事件不能因客户端已推进游标而永久遗漏。

游标过期明确返回 `CURSOR_EXPIRED` 和重新同步指引。重建快照时给出与之匹配的事件水位，再消费之后事件，覆盖快照与订阅切换窗口。过滤订阅也必须能安全推进水位。保留期、访问权限及撤权均适用于事件接口。SSE 后置，不改变交付语义。

### 4.6 同账号多 Agent 协作的最小闭环

详细接口、数据模型与实施任务见[同账号多 Agent 协作首版设计](multi-agent-collaboration-design-2026-11.md)。

**身份模型**：账号仍是授权主体；每次运行注册独立 `agent_session_id`，关联仓库、所属账号、客户端类型、可读名称、启动时间和可选任务 ID。服务端签发不可猜测的会话标识并绑定已认证主体；展示名和客户端类型只是自报信息，不能作为授权或“人类批准”的证明。每个请求仍检查当前账号权限；会话过期、撤权或结束后不能继续写入。无法可信区分人类与 Agent 的凭据不能仅凭客户端声称满足人类批准。会话续接须重新认证，并按权限校验，不凭 session ID 接管。

**工作与沟通**：提供仓库内任务线程，记录目标、关联 issue/PR、负责人会话、分支、预期路径和状态（待处理、进行中、等待、完成、阻塞）。Agent 可向任务线程发消息、回复、@会话、请求协助或声明阻塞；消息带稳定 ID、会话、时间、线程和关联 SHA，支持分页和游标续读。消息内容属于不可信输入，不能覆盖用户指令或自动授权操作。初期用 REST 和 MCP 提供创建/读取/回复/状态更新，优先适配现有工具；账号权限和仓库访问规则适用于所有会话和消息。

**发现和交接**：工作区提供活跃会话、关联任务、最近状态和未读/待处理消息；心跳和租约过期后标记离线或未知，不能据此认定工作完成。交接包含目标、已完成事项、当前 SHA、改动范围、验证证据、阻塞和下一步，接收方可确认接收；声明与服务端验证分开。路径重叠发出建议性提示，不视为锁，Git ref CAS 仍是最终保护。消息与任务状态持久化，支持断线重连、消息去重及重新同步；实时推送可后加。

**产品边界**：协作范围默认限于授权仓库，通知按目标会话和账号权限过滤；避免向日志或消息复制凭据。每个操作和消息保留账号、会话、任务关联，历史会话结束后仍可追溯。会话是协作身份而非独立安全主体；需要可信主体区分或细粒度授权时仍依赖受限凭据与服务端策略。

### 4.7 交接与评测

工作声明包含 task、主体、分支、预计路径、有效期；过期声明不阻断写入。交接记录包含产物 SHA、未完成事项、验证记录 ID、待决问题和操作 ID。Agent 的完成声明与服务端验证分字段存储；平台不推断声明一定真实。

早期固定真实任务集并记录请求数、返回字节、耗时、恢复次数、最终代码与证据是否匹配。token 由 harness 侧记录模型和分词口径。比较使用相同任务、初始 SHA、环境与配置；模型版本、失败样本和重复次数均留档。不得用 mock 结果代替真实 Git/CI 闭环。

## 5. 整合优先级与实施顺序

P0 表示可靠闭环与开放写工具前的必需项；P1 表示效率与接入增强；P2 表示后续扩展。优先级不是要求所有工作串行，也不代表实施已获发布授权。

| 阶段 | 优先级 | 交付范围 | 依赖 / 对应 Claude 阶段 | 退出条件 |
|---|---|---|---|---|
| S0 基线核验 | P0 | 核验已有 tree/search/CI 反馈；记录差距、真实流程基线与测试结果 | H0、H1 在制实现 | 已有实现有明确 SHA/工作区说明与验证记录；失败项有归属 |
| S1 可靠读取与协作首版 | P0 | 会话注册、任务线程、消息、状态与交接；并行推进快照、索引版本和 CI 证据 | S0；整合 H1、H2 部分 | 同账号会话可互相发现、沟通和续接；跨页不混版本，旧 CI 不满足新提交 |
| S2 身份与基础写契约 | P0 | 受限身份、统一 RefPolicy、CAS、结构化恢复、幂等、纯 dry-run | S0；H3、H4 | 所有 ref 写入口受控，同键并发单效果，dry-run 零业务副作用 |
| S3 可恢复执行 | P0 | operation、持久计划、outbox、事件长轮询及故障对账 | S2；证据相关校验依赖 S1；前移 H6 的事件部分 | 断连/重启/部分成功可查可恢复，旧计划拒绝，事件可重放 |
| S4 客户端闭环 | P0 门禁 / P1 接入 | rg-client、只读 MCP 扩展、写工具、ifg 高频流程 | 只读与 S1 同步；写工具依赖 S1–S3；H2、H5 | REST/MCP/CLI 关键语义一致，真实受限 Agent 完成闭环 |
| S5 协作增强与重放 | P2 | 路径重叠提示、PR 历史对象保活与 export；有需求再做 SSE/远程 MCP | 协作增强可早于 S4；重放依赖相关 Git 能力；H6 重放部分 | 删除源分支后历史版本可取，交接可核对，权限无旁路 |

S1 与 S2 可独立推进；共享 DTO/客户端骨架可在 S0 后开始，不等待全部服务端能力。S2 的低层正确性修复不必等身份功能完成，但对外开放写工具必须同时通过身份与可靠写门禁。远程 MCP 若有明确接入需求可在只读阶段提前，不以新增传输阻塞核心验收。

建议首批任务拆分：S0 核验 → S1 会话与任务消息、交接、快照契约与 CI 关联四项 → S2 身份入口矩阵、CAS/幂等、dry-run 三项 → S3 operation 对账、计划、事件三项 → S4 端到端接入。每项单独评审与记录验证，不一次重构全部 API。

## 6. 验收矩阵

| 编号 | 场景与方法 | 必须满足的结果 |
|---|---|---|
| A01 快照 | 真实仓库先取 tree 第一页，在 barrier 后推进分支，再取后页与文件 | 同快照完整重组，或明确快照失效；不混入新版本 |
| A02 搜索 | 索引 A 后推送 B，同时触发索引重建并查询 | 返回准确 `indexed_commit` 和 freshness；内容与标注一致 |
| A03 证据 | A 通过后推 B；分别推进 base、重跑、跳过和取消检查 | B 不能继承 A 的通过；目标分支相关证据按候选版本失效；自述不满足门禁 |
| A04 日志与等待 | 含中文/ANSI/跨分片 secret 的真实日志；多次 offset 读取、撤权和状态切换 | 无泄露、不截断 UTF-8、偏移语义稳定、无权拒绝、终态/超时正确；启发式有标注 |
| A05 权限入口 | 枚举 HTTP/SSH push、编辑、分支/tag、三种合并及队列；覆盖 token 过期、撤权、仓库隔离 | 每个入口均受策略约束；Agent 自批不满足人类批准；系统主体也不可旁路 |
| A06 CAS | barrier 同步两个写者，使用同一期望 ref | 恰一个更新成功；另一个结构化冲突，不覆盖胜者；新分支使用不存在前提 |
| A07 幂等 | 同键同体并发、响应丢失后重试、同键异体、跨仓库/动作 | 单一业务效果；可查同 operation；异体明确拒绝；不同命名空间不误命中 |
| A08 dry-run/计划 | 前后快照 refs、DB、审计、队列；预览后改 ref、策略、批准或等过期 | dry-run 无业务副作用；持久计划创建与其区分；变化后执行拒绝且无目标写入 |
| A09 故障恢复 | 在持久意图、ref 更新、DB 结果和 outbox 投递边界注入进程退出，再重启 | 最终结果可解释；不重复提交、不覆盖外部推进；不确定时 needs_attention；下游可恢复 |
| A10 事件 | 并发事务交错提交、投递重复、断线续传、过滤、游标过期、快照切换与多实例 | 不永久漏已提交事件；重复可去重；过期显式重同步；权限实时检查 |
| A11 真实任务 | 固定初始 SHA，受限 Agent 完成建分支→提交→PR→CI 失败→修复→批准后入队；中途换会话 | 结果与提交证据一致，越权被拒，接手无需猜测操作结果；记录成本和恢复路径 |
| A13 同账号沟通 | 两个不同客户端使用同一账号注册独立会话，围绕同一任务发消息、标记阻塞、交接并在断线后续读；第三个无仓库权限账号尝试访问 | 会话与消息来源可区分；交接和未读可恢复，重复消息可去重；无权访问被拒；客户端自报身份不改变授权或批准资格 |
| A12 交接与保活 | 删除源分支后 checkout 历史 PR；读取交接；模拟声明过期和路径重叠 | 承诺保留的对象仍可读，交接指向实际证据，协作提示不构成写锁 |

并发测试使用 barrier/可控故障点保证交错，不能仅靠 `join!` 或 sleep 声称覆盖竞态。A09 的故障注入验证恢复机制，A11 仍需真实 Git、CI runner 与隔离执行环境。真实 runner 不可用时明确标为待验证，不能用模拟结果关门禁。
