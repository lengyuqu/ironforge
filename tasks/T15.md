## 要求

### 1. 放宽方式（与 T14 一致）

```rust
// 改前
pub async fn list_stages(db: &DatabaseConnection, pipeline_id: i64) -> Result<Vec<_>, DbErr>
// 改后
pub async fn list_stages<C: ConnectionTrait>(db: &C, pipeline_id: i64) -> Result<Vec<_>, DbErr
```

参数名保留 `db`、泛型名 `C`、用 `sea_orm::ConnectionTrait`。

### 2. 调用点豁免（这次提前授权）

**泛型 `&C` 不参与 deref coercion**（T14 已证实）。`&Arc<DatabaseConnection>` 或 `&&DatabaseConnection` 形态的调用点会编译失败，**允许你改成 `db.as_ref()` / `*db`**，条件是：

- 只改这一个 token，不许改调用点的其他任何内容
- 逐条列进报告（文件:行、原形态、改法）
- 如果某处需要的不止是解引用（比如要 clone、要 move、要改签名链），**停下报告**

`rg-ci`、`rg-core`、`rg-http`、`rg-runner` 都可能调用 `pipeline_ops`，本轮允许这些文件的**单 token 解引用**改动。

### 3. 不许改语义

SQL 条件、排序、错误信息、返回值、`pipeline` 状态机转移逻辑一个都不许动。这是一次纯签名泛化。

### 4. 连锁处理

改一批 → `cargo check -p rg-db` → 按错误分类（该放宽的一并放宽 / 确实需要保留的保留）→ 反复到干净。然后 `cargo check --workspace --all-targets` 处理调用点。
