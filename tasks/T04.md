## Task Constraint

在 Git 写入路径上做增量密钥扫描，命中按规则分级处置（拒绝 / 记事件），**不阻断正常推送**。

已核实锚点（`c7d70df` 时点，行号会漂）：

- 接收路径：`crates/rg-git/src/protocol/receive_pack.rs` —— `:432` 拒绝、`:481` 签名策略、`:507` 改 ref。扫描器必须能在 **`:481` 与 `:486` 之间**被调用。
- REST 提交路径（4 处，均走 `commit_tree_edits`）：`crates/rg-core/src/repo/service.rs` 的 `create_or_update_file_with`、`update_files_in_commit`、`delete_file_with`（不产新 blob，可跳过）、`commit_batch`。
- **`rg-git` 不依赖 `rg-core`**，扫描器必须放 `crates/rg-git/src/secret_scan.rs`，不能放 rg-core。
- 拒绝形态：push 侧是纯文本 report-status `ng <ref> <message>`（`:680`）；REST 侧是 `AppError::Coded`（`crates/rg-http/src/error.rs:61-74`），`CoreError`（`crates/rg-core/src/error.rs:24-44`）**没有** code/reason 变体 —— 需要加变体或由 handler 映射。
- `rg-git` 无 DB：事件由调用方（rg-core / rg-http）写，扫描器只返回结果。

## 规则集与处置（协调者已定口径，直接实现，不要再问）

| 规则 | 示例 | 处置 |
|---|---|---|
| 私钥头 | `-----BEGIN (RSA\|EC\|OPENSSH\|PGP) PRIVATE KEY-----` | **硬拒** |
| 云 AK | `AKIA`/`ASIA` + 16 位、`LTAI`、`AKID` | **硬拒** |
| 平台 PAT | `ghp_`/`gho_`/`ghs_`、`glpat-`、`ifs_` 前缀 | **硬拒** |
| JWT | `eyJ` 开头的三段 base64url | 记事件 + 警告 |
| 通用高熵 | 长度 ≥ 32、Shannon 熵 ≥ 4.5 的裸串 | 记事件 + 警告 |

允许列表：路径 glob（如 `**/*.md`、`**/testdata/**`）、行内标记 `ironforge:allow-secret`（同行生效）。

**扫描范围**：只扫**新增 blob**（不做全历史）。约束：单文件 ≤ 1 MiB、单次 ≤ 500 文件。

**超限口径（协调者裁决 = fail-open）**：超过 500 文件时**整批跳过扫描**，但必须产出 `secret_scan_skipped` 审计事件（含 ref、文件数、原因），由调用方写入；不得静默跳过。理由：首次导入大仓是真实场景，硬拒会阻断迁移；事件让管理员可见。
