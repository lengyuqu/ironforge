## 要求

### 1. 表 + 迁移

`agent_draft_namespaces`（窄表）：`id`、`prefix`（如 `agent/42/`）、`repo_id`、`owner_user_id`、`ttl_secs`、`expires_at`、`grace_secs`、`state`（`active` / `expiring` / `deleted`）、`created_at`、`extended_count`。

- 迁移 `crates/rg-db/src/migrations/m20261115_000001_create_agent_draft_namespaces.rs`，显式表名、`has_table`/`has_column`/`has_index` 守卫、`up` 幂等。
- `Migrator::down` 步数 **28 → 29**。
- **注意**：T06 交付的 `m20261114_000002` 与本迁移相邻，`rg-db` 那个 `upgrade_keeps_child_rows_triggers_and_foreign_keys` 会校验步数，别漏改。

### 2. 推送守卫（核心）

`post_push_hooks` 里，对被推 ref 判是否为草稿分支（查表匹配 `prefix`）：

- **仍跑 CI**（这是需求成立的前提）
- **跳过**：push webhook、分支事件 webhook、ws 通知、邮件
- **仍写 `repo_events`**：agent 要能 `wait_repo_events` 等自己的推送结果
- 为此把 `webhook/service.rs::trigger_event` 拆成 `record_event`（只写 `repo_events`）与 `trigger_event_quietly`（不投递但不留虚假成功）。**不要**用「传一个 bool 关掉全部」的写法——那会让后续新增的投递通道默认被漏掉。

### 3. 清理任务

- 1h 轮询（照 `task_supervisor`）
- `expires_at` 到期：**先关闸**（`state = expiring`，拒新推送）→ 等 `grace_secs` → 才删
- 删除走 `delete_ref_if` 的 CAS 直删，**绕开 `on_delete` 守卫**，并把「故意绕过护栏」写进审计（`agent_draft.cleaned`，含被绕过的原因）
- 若 ref 已不存在，标记 `deleted` 而非报错

### 4. REST 端点（四个）

`POST /repos/{o}/{n}/agent-drafts`（建）、`PATCH .../{id}`（续期，最多累到初始 TTL 的 4 倍）、`DELETE .../{id}`（软删）、`GET /repos/{o}/{n}/agent-drafts`（列）。

路由三处必须同时补齐：`lib.rs` 路由段、`openapi.rs`、`route_meta.rs`。

### 5. 安全边界（**硬要求，不做就别交付**）

复核已确认 `ci_secrets` 没有按 ref 过滤的能力。所以：

- **草稿分支运行时完全不注入 secrets**（不是「按 ref 过滤」，是直接不注入）。
- **草稿分支忽略 `allow_host_execution`**，只许容器内执行。
- 这两条要在代码里有明确分支 + 测试，并在 plan 里写成「这是本功能的安全前提，不是可选优化」。

理由：草稿分支跑的是推送方自带的 CI 配置，若允许 host execution 或注入 secrets，等于开了一条绕过人工 review 的任意代码执行通道。
