## 三处现状（已逐行核实，基线 `6aa1337`）

| # | 位置 | 查库方式 | 查不到账号 | 返回 |
|---|---|---|---|---|
| 1 | `rg-http/src/api/auth.rs:165 ensure_reviewer_may_approve` | `find_by_id` → `is_agent` | 403 `no such account` | `AppError` + `with_reason(AGENT_MAY_NOT_APPROVE, ...)`；**另有分支受限 token 检查**（`ref_allowlist`） |
| 2 | `rg-core/src/authorization/evaluator.rs:325 ensure_human_decider` | 同上 | `forbidden("only a person may approve")` | `CoreError::coded(403, "AGENT_MAY_NOT_APPROVE", ...)` |

**行为其实一致**（查不到就拒，fail-closed），差异只在错误包装和 #1 的额外检查。

## 改法：提取纯判定，错误各自保留

**不要**把三处合并成一个返回 `CoreResult<()>` 的函数——那会强迫统一错误结构，破坏现有 `with_reason` 的可操作提示，可能打到契约测试。

在 `crates/rg-core/src/agent.rs` 加**纯判定**：

```rust
/// Whether `user_id` is an account a decision may come from.
///
/// Returns `Ok(false)` for an unknown or soft-deleted account: an unreadable
/// account must not read as "not an agent". This is the single place the
/// "agents may not approve" rule learns *who* the actor is; callers keep their
/// own error shapes.
pub async fn is_human_account(db: &DatabaseConnection, user_id: i64) -> CoreResult<bool>
```

实现：`user_ops::find_by_id` → `Ok(user.is_some_and(|u| !is_agent(&u)))`，DB 错误向上传播。

然后三处各自改成：

```rust
match rg_core::agent::is_human_account(db, user_id).await {
    Ok(true) => {}
    Ok(false) => return /* 该处原有的 403，一字不改 */,
    Err(e) => return /* 该处原有的 internal */,
}
```

- **#2 的 `ensure_human_decider` 保留**（它是 core 的公开 API，别删），内部改为调用 `is_human_account`，错误信息保持原样。
- **#1 的分支 token 检查保留在原位**，`is_human_account` 只接管「是不是 agent」这一半。

## 验证

1. **三处行为不变**：`pr_review_tests` / `authorization` 相关 / `ci_environments` 相关测试全绿
2. **`is_human_account` 单测**：人类 → true；agent → false；不存在 id → false；软删用户 → false
3. **变异测试（关键）**：把 `is_human_account` 临时改成对 agent 也返回 `true`，然后确认**三处各自的测试都变红**（PR approve 的、授权票的、环境审批的）。只红一处说明另两处没走这个判定。撤销变异后全绿。
4. 错误信息**逐字不变**：至少各取一条现有测试，断言 403 的 `message` 与 reason 与改动前一致
