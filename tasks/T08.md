## 要求

### 1. 端点契约

`POST /repos/{owner}/{name}/commits/apply-patch`

```jsonc
{
  "branch": "feature/x",
  "expected_sha": "<40 位，必填>",
  "patch": "diff --git a/... b/...\n...",   // unified diff 文本
  "message": "optional, 缺省生成",
  "dry_run": false
}
```

- 分支不存在**不创建**（与 pick 一致）；`expected_sha` 与当前分支头不一致 → 409 `REF_ADVANCED`。
- `dry_run: true` 只校验能否干净应用，**不落 ref、不写审计、不触发 CI/webhook**，返回将产生的 tree/文件变更摘要。
- 成功返回 `{ commit_sha, tree_sha, files_changed, dry_run }`。

### 2. 应用实现（推荐临时 index 路线）

gix 没有 apply 原语。推荐：

```
GIT_INDEX_FILE=<临时文件>
git read-tree <expected_sha>            # 用目标提交的树初始化临时 index
git apply --cached <patch>              # 只改 index，不碰工作区
git write-tree                          # 得到新 tree
git commit-tree <tree> -p <expected_sha> -m <message>
```

- 全程通过 `GitCommandGateway::run_with_env` 传 `GIT_INDEX_FILE`，**不要**在工作区里 checkout（裸仓没有工作区）。
- 临时 index 必须落在 `tempfile` 目录并在 `Drop` 时清理。
- 若 `git apply` 需要 `--3way` 才能落地，必须先定义清楚：什么算冲突、`--3way` 自动解决后要不要在 commit message 里标注。**不允许**默认开 `--3way` 而不记录口径。
- 若评估后认为临时 index 路线不可行（例如裸仓 + `GIT_INDEX_FILE` 有坑），可改自实现 diff 解析 + 树构建，但必须在 plan 里写清为什么放弃前一条，以及支持哪些 diff 子集（新增/删除/修改/重命名/二进制）。

### 3. 安全（本任务的重点，别省）

- **路径穿越必须拒绝**：patch 里的 `+++ b/../../x`、绝对路径、`.git/` 内部路径一律 400。这一条要有测试。
- **体积上限**：patch 文本 ≤ 1 MiB、影响文件数 ≤ 500。超限 413 或 400，**明确选一个并写进 plan**（不要 fail-open，这是写入路径）。
- 新 blob 必须过 R7 密钥扫描（`rg-git/src/secret_scan.rs`），命中按硬拒规则处理，返回 422 `SECRET_DETECTED`。
- 权限：需要 `can_write_repo`；agent token 走与推送相同的 scope 校验。

### 4. 副作用（必须与推送路径一致）

- 推进 ref 用 CAS（`PreviousValue::MustExistAndMatch(expected_sha)`），不能盲写。
- 触发 CI（`trigger_pipeline`，`trigger_type` 用 `"api"` 或明确的 `"apply_patch"`，`triggered_by` 传 actor id）。
- 触发 webhook（与文件提交路径同一套事件）。
- 写审计日志。
