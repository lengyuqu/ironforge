**① 事件写入的事务性与 outbox（#15）**

内容要点（每条都要在代码里核实位置）：
- `rg_db::ops::repo_event_ops::append<C: ConnectionTrait>` 可接受事务连接
- `webhook::service::record_event_in_txn` / `deliver_event` 的语义分工（前者失败回滚，后者失败只 warn）
- 5 条已迁移路径：`issue.opened` / `pull_request.merged` / `release.created` / `pull_request.opened` / `pull_request.closed`
- **`pr.closed` 曾经是「先发 webhook 再写库」**，已修正为写后发
- `repo_events.dispatched_at`（迁移 `m20261117_000001`）：语义是「已交给投递系统」不是「投递成功」；`NULL` = 待补投
- 静默路径（`record_event` / `trigger_event_quietly`，草稿区）写入即标记 dispatched，**sweep 绝不补投**——否则草稿 push 会被投给所有 hook
- `webhook::outbox::run_sweep_loop`：60s 周期，窗口 `[now-15min, now-2min]`，环境变量 `IRONFORGE_WEBHOOK_OUTBOX_SWEEP_SECS`
- 遗留：仍是至少一次投递；commit↔spawn 崩窗会被补投可能重复；超 15 分钟不补

**② 通用审批原语（#19）**

- 三表 `authorization_requests` / `authorization_decisions` / `authorization_sets`（迁移见 `migrations/` 里 `authorization` 相关那几条）
- `authorization::evaluator` 的授权集求值器；`consume` 的 CAS（`UPDATE ... WHERE state='pending'`，影响行数 0 → 409）
- `scope_expand` 执行面：**subject 格式 `"{token_id}:{target_scopes}"`**，目标 scope 编码进 subject 才能进 `payload_hash`（`payload.rs:22` 的 canonical form 是 `(repo, action, subject, head_sha)`，没有 parameters 列）
- **`agent::is_human_account`** 是「这个账号能否做出决策」的**唯一**判定（人类 true / agent false / 不存在 false / 软删 false），三处消费：`ensure_reviewer_may_approve`、`ensure_human_decider`、CI 环境审批
- `issue.closed` **没有搬进事务**：`update_issue` 里 labels/assignees 是 fail-soft，包事务会把「标签没设上」变成「整个更新回滚」
- `milestone.closed` **不该改**：纯通知函数、无业务写

**③ CI 容器隔离（#41）**

- `DockerLimits::default().user` = **IronForge 进程自己的 uid:gid**（`libc::getuid/getgid`，不是 `Command::new("id")`——`id` 在 distroless 镜像里不存在会静默回退 root）
- `IRONFORGE_CI_RUNNER_USER`：空 = 进程 uid:gid；`root`/`0` = 回退镜像默认（并 `warn!` 一次）；其它原样传
- 未做：daemon 级 userns-remap、seccomp/AppArmor 沙箱

**④ 符号图（#63）**

- 表 `symbol_commits` + `symbol_definitions`（迁移 `m20261118_000001`，`Migrator::down` 31→32）；**只有 2 个索引**（`uq_..._anchor` 幂等锚点 + `idx_..._lookup`按名查询），path 查询由锚点前两列服务
- 索引：`SymbolIndexer` 复用 `OutlineIndexer::extract`；`index_commit` 先删后插 + 写入即修剪；保留深度 `D = clamp(⌊128MiB/(224B×行数)⌋, 1, 6)`
- 查询：`GET /ai/repos/{o}/{r}/symbols` + core `find_symbols` + MCP `find_definition`
- **`partial` 恒为 `true`**（T28 没存每 commit 解析失败数，`partial:false` 是无证据的断言）；`limitations` 是静态已知为真的描述
- **缺索引 404 不回落 HEAD**（回落会给出另一个 commit 的定义，比报错更糟）
- **查询无条件排除 `kind='impl'`**（那些行名不是标识符，实测 684 行）
- 实测：本仓 12,208 定义 / 2.94 MiB / commit；**引用部分经实测否决不实施**（体积 30 倍、73.9% 是通用名噪音）

### 3. 「重要踩坑」补 3 条

现有踩坑按 `### N. 标题` 编号，接着往后编。

**候选三条（这轮真实撞到的，都有具体证据）**：

1. **泛型 `&C` 不参与 deref coercion** —— 把签名从 `&DatabaseConnection` 泛化成 `<C: ConnectionTrait>(db: &C)` 后，`&Arc<DatabaseConnection>` / `&&DatabaseConnection` 的调用点必须显式 `db.as_ref()` / `*db`。T14/T15 撞了 3 处。
2. **收紧一个字段的格式时，必须复查所有 `parse` 它的地方的失败分支** —— `scope_expand` 的 subject 从 `"10"` 改成 `"10:repo:write"` 后，`ensure_decider_is_not_the_agent_owner` 里的 `subject.parse::<i64>()` 恒失败且**放行**，守卫静默失效。这类坑会以「测试全绿」的形态留下。
3. **`POST /contents` 与 `DELETE /contents` 会 spawn 后置钩子** —— 测试里想「只移动分支」必须绕开钩子（用 `create_or_update_file_with` 直接调 service），否则任何依赖 recorded head 的断言都有毫秒窗口竞争。T25 修的那个 flaky 就是这个。
