# Task T05 - [#40] R10 配额与用量（最小闭环）

> 本文件是该任务状态的唯一权威；`TASKS.md` 只放镜像索引。

## Task Constraint

只做**最小闭环**：`每 agent 每仓库 CI 并发数` + `每日 CI 分钟数`，落库计数并在触发时硬限制。**不加 REST 查询端点**（留给后续任务，避免抢路由注册）。

已核实锚点（`c7d70df` 时点，行号会漂）：

- 触发入口：`crates/rg-ci/src/lib.rs:114` 的 `trigger_pipeline`。
- 现有预算表是**纯信息性**的（`collab_task_budget` / `collab_task_usage` 实体在 `crates/rg-db/src/entities/`），usage 靠客户端上报、平台不测量 —— 本任务**不复用**它们，另起平台侧计数表。
- 迁移注册：`crates/rg-db/src/migrations/mod.rs` 末尾现为 `m20261110_000002`；`crates/rg-db/src/lib.rs:1028` 的 `Migrator::down(&db, Some(26))` 必须同步改成 `Some(27)`。
- 现有 CI `concurrency` 配置（`crates/rg-ci/src/config.rs:32`）是 **pipeline 级序列化组**，与本任务的**配额**语义不同，不要混。

## 要求

1. 新表 `usage_counters`：`(id, subject_kind, subject_id, repo_id, metric, period_start, value, updated_at)`；`(subject_kind, subject_id, repo_id, metric, period_start)` 唯一索引。metric 首批两个：`ci_minutes`、`ci_concurrent_pipelines`。
2. 迁移文件 `crates/rg-db/src/migrations/m20261114_000001_create_usage_counters.rs`：
   - 显式表名（**不要**用 `#[derive(Iden)]` 的单数默认，见 `CLAUDE.md` 第 13 条）
   - `has_column` 守卫、`up` 幂等、`down` 正确删除
   - 注册进 `migrations/mod.rs`，并把 `Migrator::down(&db, Some(26))` 改成 `Some(27)`
3. 限制点：`trigger_pipeline` 入口，在创建 pipeline 之前检查
   - **并发**：该 agent 在该仓库当前 running/pending 的 pipeline 数 ≥ 上限 → 409 带稳定码（如 `CI_QUOTA_CONCURRENCY`）
   - **分钟数**：当日累计 `ci_minutes` ≥ 上限 → 409 带 `CI_QUOTA_MINUTES`
   - 上限取值：**先做成常量并集中在一处**（例如 `rg-ci` 的 `quota` 模块），并在 plan 里写明数值与依据；不要散落硬编码
4. 计数口径：pipeline 结束（成功/失败/取消）时按 `pipeline_jobs` 的 `started_at`/`finished_at` 累计分钟数到当日 `period_start`（UTC 日）。**必须幂等**（同一 pipeline 只累加一次）。
5. 只对 **agent 主体**生效（`users.kind = "agent"`）；人类主体不限制（避免误伤现有用户）。若实现上难以区分，先在 plan 里说明并降级为"记录但不阻断"。
