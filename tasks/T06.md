## 要求

### 1. 两张表 + 迁移（照方案 §二，不要自己改模型）

`authorization_requests`：
```
id（自增，刻意不用 UUID：要能按 id 盲审）
repo_id, action, subject, head_sha (nullable)
requested_by_kind, requested_by_id
authorization_set_id
state  pending | consumed | expired | denied | revoked
expires_at, consumed_at, consumed_by, consumed_effect_hash
client_request_id, payload_hash
```

`authorization_decisions`：每个批准人一行，唯一键 `(request_id, decider_user_id)` 挡重复票（语义照 `ci_environment_ops::add_approval` 的 `Ok(false)` 重复票）。

迁移文件 `crates/rg-db/src/migrations/m20261114_000002_create_authorization_requests.rs`：显式表名（`CLAUDE.md` 第 13 条）、`has_column` 守卫、`up` 幂等、`down` 正确删除；注册进 `mod.rs`；`lib.rs:1028` 步数 27 → 28。

`action` 是**平台枚举值**，不接受客户端自由字符串。

### 2. 状态机（核心，做错就变成"批准后永久开锁"）

- **消费点 = 动作真正执行时**；执行与置 `consumed` 必须在**同一事务**，带 `UPDATE ... WHERE state = 'pending'` 守卫，影响行数 0 → 409 `AUTHORIZATION_ALREADY_CONSUMED`。
- 执行成功写 `consumed_effect_hash`（合并出的 sha / 发布的版本 id）。
- 执行失败：幂等可重试的动作**退回 `pending`**（不消耗票）；不可幂等的（推镜像、真发布）**直接作废**，需重新申请。
- `head_sha` 一变，旧请求**自动标 `expired`**（理由 `head_sha_changed`），**不删除** —— 现状是"过滤"而非"状态失效"（`pr_review_ops.rs:74` 按 `commit_id == head_sha` 过滤），抽象要把这件事件化。
- 判据统一走 `normalize_commit_sha`（`crates/rg-core/src/collaboration/message.rs:72`），**不要**在审批侧自写短 SHA / 大小写处理。

### 3. 授权求值器（收敛，不新造）

一个求值器回答"谁能批这个 request、要几票"：
- 输入 `(repo_id, action, subject)`，输出 `{ approvers: 集合, required_approvals: n }`
- 内部收敛上述三处判定，但**行为必须与现状逐条等价**（协作成员的绕过缓存要保留，CI 的 admin 分支要保留）
- **硬约束写死**：申请人 ≠ 批准人（一处判定，三处复用）
- agent 凭 `requested_by_kind = agent_session` **只能申请**，approve 一律 403 —— 不看 scope

### 4. 修越权（本任务唯一的行为变更）

`submit_review` 的 `require_authenticated_read` 收紧为：**approve / request_changes 需要写权限（或明确的审批人身份）**，`comment` 类动作保持只读即可投。

- 这是**故意的行为变更**，必须在 plan 里单独列出「谁被挡住、原来能做什么」。
- 若现有测试假设"读权限即可 approve"，**改测试，不许放宽实现**。改哪几条要逐条列在 plan 里。
- 自批拒绝（`:331`）保持不变。

### 5. 幂等三元组

`client_request_id` + `payload_hash`（repo + action + subject + head_sha + parameters 的哈希）。批准时**重算 payload_hash 并比对**，不一致拒绝 —— 防的是"申请时 SHA 是 A，批准后换成 B"的 TOCTOU。
