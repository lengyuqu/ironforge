# Task T21 - [#19·步骤6 补丁] `scope_expand` 目标 scope 必须绑定进票据

> 本文件是该任务状态的唯一权威；`TASKS.md` 只放镜像索引。

## 为什么要做这个补丁

T20（`1160bb4`）实现了 `scope_expand` 执行面，但留下一个**真实的安全缺口**：

> 无 parameters 列 ⇒ 批准绑定的是 token id，不是 target scope。执行面能拒绝收缩与 user/admin，但**无法证明执行目标 = 批准人当时看到的目标**。

具体后果：批准人批准的是「把 token 10 扩到 `repo:write`」，执行时可以传 `target_scopes = "repo"`（最大权限）——「扩大」语义校验会通过（`repo` 覆盖 `repo:write`），于是**实际扩权比批准的大**。批准人无从阻止。

## 修法（不改迁移）

已核实 `crates/rg-core/src/authorization/payload.rs:22`：

```rust
pub fn payload_hash(repo_id: i64, action: Action, subject: &str, head_sha: Option<&str>) -> String
```
`payload_hash` **包含 subject**，且 `payload.rs` 顶部文档写明「Step 1 has no `parameters` column … Adding one later means adding a column and a migration」。

**所以把目标 scope 编码进 `subject`**：`subject = "{token_id}:{target_scopes}"`，例如 `"10:repo:write"`。这样 hash 自然覆盖目标，篡改会被批准时的 hash 比对挡住，不需要新列、不需要迁移。

## 要改的四处

### 1. subject 格式（`scope_expand` 专用）

- 格式：`{token_id}:{target_scopes}`，token_id 为十进制正整数、无前导零，scopes 为逗号分隔的 repo 系列 scope（沿用 `normalize_scopes` 的输出形式）。
- 申请侧（构造 request 的地方）用这个格式。
- `action.rs` 里 `ScopeExpand` 的注释补一句格式说明。

### 2. `evaluator.rs` 的 subject 校验

原来只校验「是数字」，现在要解析两段：
- `token_id` 必须正整数且与 `u64` 往返一致（拒绝 `0`、`-3`、`007`、`1.5`、空串）
- `scopes` 必须通过 `agent::validate_agent_token_scopes`
- 缺少冒号、多段、任一段非法 → `invalid_input`

### 3. `scope_expand.rs::consume_scope_expand` 的校验

- **必须 `request.subject == format!("{token_id}:{target_scopes}")` 精确匹配**，不一致即拒绝（用 `invalid_input` 或专门的 `SCOPES_CHANGED` 码，自己定，plan 说明）
- 原来的「target 必须覆盖 current」语义校验**保留**，但它**不能替代**精确匹配 —— 现在两道都要
- 这样「批准 `10:repo:write`、执行传 `repo`」会在 subject 匹配这一步被拒（`"10:repo" != "10:repo:write"`）

### 4. 测试

必测：

1. **`the_target_scope_cannot_be_widened_beyond_what_was_approved`**：申请 `10:repo:write`、批准后调 `consume_scope_expand(token_id=10, target_scopes="repo")` → **拒绝**，token scopes 未变、票据仍 pending
2. **narrowed 也不行**：批准 `10:repo:write` 后传 `"repo:read"` → 拒绝（subject 不匹配）
3. **完全一致则成功**：既有第 5 条测试改造成新格式后仍绿
4. **hash 敏感性**：`payload_hash(.., "10:repo:write", ..) != payload_hash(.., "10:repo", ..)`（直接断言两个 digest 不等）
5. **格式校验**：`"10"`（缺 scopes）、`"10:"`、`":repo:write"`、`"10:repo:write:extra"` 全部 `invalid_input`

**不要删掉 T20 的第 9 条事务性测试**（`a_consume_failure_rolls_back_the_scope_change`），只改 subject 格式。
