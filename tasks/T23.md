## R19-2：自批守卫下沉 core

**现状**：`pr.author_id == user_id` 的自批检查**只在 HTTP 层**（`crates/rg-http/src/api/reviews.rs:331`）。`crates/rg-core/src/review/service.rs:57` 的 `submit_review` 只校验 PR 存在 + `state == "open"`，然后直接 `pr_review_ops::create`。

**风险面已核实**：MCP **没有**暴露 `submit_review`（`grep -rn "submit_review" crates/rg-mcp/` 无结果），所以当前不是可利用的漏洞。但这是结构性隐患——任何未来新增调用面（MCP 工具、内部服务、批量导入）都会绕过自批守卫。

**改法**：`submit_review` 的签名已有 `reviewer_id: i64`，直接在 core 加：

```rust
// 位置：拿到 `pr` 之后、任何写库之前
if matches!(action, ReviewAction::Approve | ReviewAction::RequestChanges)
    && pr.author_id == reviewer_id
{
    return Err(CoreError::invalid_input(
        "a PR author cannot approve or request changes on their own PR",
    ));
}
```

（`ReviewAction` 的实际变体名先读代码确认，不要照抄。）

**HTTP 层的守卫保留**——它现在会先于 core 触发，返回 400 `AppError::bad_request`，行为不变。core 这道是给非 HTTP 调用面的兜底。**不要删 HTTP 层那道**，删了会改变现有错误码。

**注意**：`reviews.rs:883` 是第二处 `submit_review` 调用（隐式 Comment 评审），`action` 是 `Comment`，不会命中上面的分支。

## R19-3：邮件文案与实际不符 + `<br/>` 被转义

**两处，都在 `crates/rg-core/src/email/mod.rs`**：

1. **`:106` 的尾句是假的**：
   ```html
   You received this email because you have notifications enabled on IronForge.
   ```
   系统**没有**通知开关（`user` 表无此字段，`notifications` 表无偏好列）。这句话在为一个不存在的设置背书。

   改成不依赖开关的表述，例如：
   ```html
   You received this email because you are involved in this repository on IronForge.
   ```
   （文案自己定，要求：**不能声称存在任何用户可配置的开关**。）

2. **`:110` 的 `html_escape(message)` 会吃掉调用方传的 `<br/>`**：
   - `html_escape`（`:118-122`）把 `<` `>` 转义成 `&lt;` `&gt;`
   - 调用方 `rg-http/src/lib.rs:3949` 附近传的 body 里含 `<br/><br/>`，渲染出来是**字面文本 `&lt;br/&gt;`**

   **改法（选这个，不要用「转义后再还原」那种）**：
   - 模板里 `{message}` 所在的 `<p>` 加 `white-space: pre-wrap;`（保留换行）
   - 调用方把 `<br/>` 改成 `\n`
   - `html_escape` **保留**（防 XSS，不能去掉）

   改完检查所有 3 个 `send_html_notification` 调用点是否有同类问题：
   - `rg-http/src/lib.rs:3949`
   - `rg-core/src/notification/dispatch.rs:292`
   - `rg-core/src/user/service.rs:745`

   **只改文案/换行，不要重构这三个调用点的逻辑。**
