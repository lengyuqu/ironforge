# Task T19 - [#15 第七步] outbox 最小版本：投递状态 + 兜底补投

> 本文件是该任务状态的唯一权威；`TASKS.md` 只放镜像索引。

## Task Constraint

前六步把 5 条事件路径搬进了事务，消除了「业务成功但事件没写」。剩下的洞是**另一个方向**：事件写了，但投递没发生。

```
事务内写事件 ✅ → commit → deliver_envelope（spawn 投递）
                              ↑ 这里崩 / 进程被杀 = 有事件、永久无投递
```

另外 `branch.*` / `tag.*` 四类事件走 git push，**根本没有 DB 事务可依附**，只能靠「先落盘再投递」的模式覆盖 —— 这也是本步要解决的方向。

**本任务只做最小可用版本**：给事件加投递状态 + 一个兜底 worker 补投漏网的。**不做**完整 outbox（不引入 pending/processing/sent 状态机、不做投递顺序保证、不做幂等键）。

## 已核实（`e6083ae` 时点）

- `repo_events`：`id / repo_id / event_type / payload / created_at`。**无投递状态**。
- `webhook_deliveries`：`id / webhook_id / event / delivery_id(UUID) / response_status / ...`。**无 `event_id`**，所以无法用「投递行是否存在」反推某事件是否已投递。
- `deliver_envelope`（`webhook/service.rs:449`）：查 `list_active_by_repo_and_event` → 每个 hook `tokio::spawn` 投递 → spawn 内部建 delivery 行。
- `append` 返回 event id（cursor），但 `record_envelope` 把它丢弃了。

## 要求

### 1. 迁移：`repo_events.dispatched_at`（可空）

`m20261117_000001_add_repo_events_dispatched_at.rs`，`Migrator::down` **30 → 31**。

- 列：`dispatched_at TIMESTAMP NULL`
- 索引：`(dispatched_at, created_at)` 或仅 `created_at`（说明理由）
- **历史行**：全部为 `NULL`。这会让 worker 第一次启动时把历史事件当「未投递」补发一遍 —— **必须避免**。worker 的扫描窗口要限定 `created_at > (部署时刻)`，或迁移时把历史行的 `dispatched_at` 回填为 `created_at`。**选后者**（回填），因为它不依赖运行时状态。

### 2. 写入时 `dispatched_at = NULL`，投递时标记

- `repo_event_ops::append` 插入时 `dispatched_at: NotSet`（NULL）。
- `deliver_envelope` 在**发出 spawn 之前**把该事件的 `dispatched_at` 置为 `now()`（语义是「已交给投递系统」，不是「投递成功」——成功与否由 delivery 行的 status 表示，失败重试仍走现有机制）。

  为什么在 spawn 前标记而不是后：spawn 是 fire-and-forget，没有回调点。在 spawn 前标记意味着「标记后、spawn 前」崩会漏（微秒级窗口）；在 spawn 后标记则 spawn 失败时会重复补投。前者窗口小且不产生重复投递，选前者。

  需要把 event id 传进 `deliver_envelope`：`append` 已经返回 id，`record_envelope` 要把它透出来（改返回类型或加一个变体函数，自己选，plan 里说明）。

### 3. 兜底 worker

新建 `crates/rg-core/src/webhook/outbox.rs`：

```rust
/// 补投「有事件、无投递」的漏网事件。
/// 扫 created_at ∈ [now-15min, now-2min] 且 dispatched_at IS NULL 的事件。
pub async fn sweep(db: &DatabaseConnection) -> Result<SweepReport>
```

- 窗口下界 `now-2min`：避开刚写完、正在正常投递的事件（防重复）。
- 窗口上界 `now-15min`：避免扫全表；超过 15 分钟还没投的，人工排查比自动补投更安全。
- 对每个事件：`deliver_envelope(db, repo_id, event_type, payload_as_value)` → 标记 `dispatched_at`。
- `SweepReport { scanned, redelivered, failed }`，`failed` 的**不要**标记 dispatched_at（下一轮再试）。
- payload 是 `Option<String>`，解析失败的事件要 `warn` 并**标记为已处理**（否则每轮都卡在它上面）。

### 4. 注册 worker

复用 T11 清理任务的注册方式（`rg-http/src/lib.rs` 里 spawn 的周期性任务）。每 **60 秒**跑一次 sweep，失败只 `warn` 不退出循环。

`rg-http/src/lib.rs` 的改动**限制在启动注册那几行**，不要碰其它逻辑。

### 5. 配置

如果已有类似 `agent_draft_cleanup_interval_secs` 的配置项，沿用同样风格加 `webhook_outbox_sweep_secs`（默认 60，设 0 关闭）。没有就不要新造配置系统。

## 验证

1. **历史行不被补发**：迁移后插一条「历史形态」的行（`dispatched_at` 为 NULL 且 `created_at` 很久以前）→ `sweep` **不**投递它。这条要单独测，它是本任务最危险的地方。
2. **漏网被补投**：造一条 `dispatched_at IS NULL`、`created_at = now-5min` 的事件 + 活跃 hook → `sweep` 投递 1 次、`dispatched_at` 被标记。
3. **正常路径不重复**：`trigger_event` 正常走完后 `dispatched_at` 已非 NULL → `sweep` 投递 0 次。
4. **窗口边界**：`created_at = now-10s` 的（窗口内下界）不被扫；`now-20min` 的（超上界）不被扫。
5. **payload 解析失败**：坏 payload 的事件被标记（不卡循环）且 `warn`。
6. **worker 幂等**：连续跑两次 `sweep`，第二次投递 0 次。
