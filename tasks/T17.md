# Task T17 - [#15 第五步] `release.created` 走事务内事件写入（原本无事务的路径）

> 本文件是该任务状态的唯一权威；`TASKS.md` 只放镜像索引。

## Task Constraint

T13（`issue.opened`）与 T16（`pull_request.merged`）搬的都是**已有事务**的路径。本任务搬一条**本来没有事务**的路径 —— `release.created`，验证「单条 insert + 事件」这个模式也能安全进事务。

**为什么是 release.created 而不是 issue.closed**：`update_issue` 里的 labels / assignees 写入是 **fail-soft**（失败只 `warn`、继续执行），把它们一起包进事务会把"标签没设上"变成"整个更新回滚"——那是语义变更。`create_release` 的业务写只有一条 insert，干净。

## 现状（`75a336b` 时点，已逐行确认）

`crates/rg-core/src/release/service.rs::create_release`：

```rust
// 校验（tag_name/title 非空） + 查重 find_by_repo_and_tag —— 都在事务前，正确
let release = rg_db::ops::release_ops::create(db, model).await?;      // 单条 insert

let payload = serde_json::json!({ id, repo_id, tag_name, title, body,
                                  is_draft, is_prerelease, author_id });
if let Err(e) = crate::webhook::service::trigger_release_created(db, repo_id, &payload).await {
    tracing::warn!("Failed to trigger release.created webhook: {e}");   // 失败只 warn
}
```

`trigger_release_created`（`webhook/service.rs:779`）只做包装：
```rust
let payload = json!({ "event": "release.created", "release": release });
trigger_event(db, repo_id, "release.created", &payload)
```

`release_ops::create(db: &DatabaseConnection, model)`（`release_ops.rs:59`）就是 `model.insert(db)`，**未放宽**。

## 要求

### 1. 放宽 `release_ops::create`

```rust
pub async fn create<C: ConnectionTrait>(db: &C, model: ReleaseActiveModel) -> Result<ReleaseModel>
```

`find_by_repo_and_tag` 如果被别处用且不需要事务，**保持原样**（减少改动面）；若编译要求也放宽，一并放宽并在报告列出。

### 2. `create_release` 改成事务

```rust
// 校验 + 查重不变（事务前）

let txn = db.begin().await.context("db: begin release transaction")?;
let release = rg_db::ops::release_ops::create(&txn, model).await?;

let payload = serde_json::json!({ /* 字段与现在逐字节一致 */ });
let event_payload = serde_json::json!({
    "event": "release.created",
    "release": payload,
});
crate::webhook::service::record_event_in_txn(&txn, repo_id, "release.created", &event_payload).await?;

txn.commit().await.context("db: commit release transaction")?;

if let Err(e) = crate::webhook::service::deliver_event(&db, repo_id, "release.created", &event_payload).await {
    tracing::warn!("Failed to deliver release.created webhook: {e}");
}
```

要点：
- **payload 逐字节等价**：内层 8 个字段（`id/repo_id/tag_name/title/body/is_draft/is_prerelease/author_id`）一个不少、顺序不变；外层 `{ event, release }` 两键。
- `record_event_in_txn` 失败 → `?` **回滚整个 release 创建**（宁可创建失败，不要"release 建好了但事件永久丢失"）。注意这与旧行为不同（旧的是 best-effort），是**有意的语义变更**，plan 里要写明。
- `deliver_event` 失败 → 只 warn，与旧行为一致。
- 校验与查重**必须留在事务外**（查重在事务内做也没意义，SQLite 无行锁；保持原位置，diff 最小）。

### 3. `trigger_release_created` 的处理

T16 先例：`trigger_pr_merged` 因无调用点被**删除**（原位留注释）。本任务同样：改写后它没有调用点，**删除**并在原位留注释说明原因。

如果它还有别的调用点（比如 `rg-http` 直接调），**不要删**，改为保留 + 加注释，并在报告说明。

### 4. 验证

1. **正常创建**：`repo_events` 里 `release.created` **恰 1 行**、receiver 收到 1 次、payload 八字段与 DB release 行一致。
2. **不重复写**：断言只有 1 行。**建议做一次变异测试**（临时让 `deliver_event` 也 append，确认测试会红——T16 用过这个手法，证明断言有效）。
3. **回滚不写事件**：release 创建失败时 `repo_events` 无该事件。可构造的真实失败点：查重命中（在事务前）、或事务内注入失败。如果只能构造事务前的失败，**如实说明**，不要编假场景。
4. **既有 release 测试全绿**。
