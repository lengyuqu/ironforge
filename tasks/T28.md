## 要做的四件事

### 1. 迁移（31 → 32）

`m20261118_000001_create_symbol_graph.rs`：

```
symbol_commits(id INTEGER PK, repo_id, commit_sha TEXT, created_at)
  UNIQUE (repo_id, commit_sha)

symbol_definitions(id INTEGER PK, repo_id, commit_id INTEGER FK→symbol_commits.id,
                   path TEXT, name TEXT, kind TEXT, start_line, end_line, signature TEXT NULL)
  索引 (repo_id, commit_id, name)   -- 按名查定义的主路径
  索引 (repo_id, commit_id, path)   -- 按文件列定义
  UNIQUE (commit_id, path, name, kind, start_line)   -- 幂等写入的锚点
```

要点：
- `up` 幂等（用 `has_column`/`has_table` 守卫，参考 `m20260712_000010`）
- `down` 可回滚（先删索引再删表，外键顺序正确）
- 外键删除行为：删 `symbol_commits` 行时级联删 `symbol_definitions`（或修剪时显式两表删，自己选并说明）
- **跨后端**：SQLite / PostgreSQL / MySQL 都要能跑（验收含 PG/MySQL up+down）

### 2. `SymbolIndexer`

放在 `crates/rg-core/src/search/symbol_indexer.rs`，**复用现有 `OutlineIndexer::extract`**，不要重写 AST 遍历。

```rust
pub struct SymbolIndexer;
// 实现 indexer.rs 的 trait（先读 trait 定义，字段照它的形状）
```

逻辑：
- 遍历仓库文件的 outline（复用现有 `supports` / `extract`）
- 对每个 `OutlineItem`（**含 children 递归**）写一行 `symbol_definitions`
- 定义名可能不是标识符（`kind = 'impl'` 的那些），**照存不误**，只在查询时排除

### 3. 写入 + 修剪（同事务）

```rust
pub async fn index_commit(db, repo_id, commit_sha) -> Result<IndexReport>
```

- 事务内：
  1. upsert `symbol_commits` 拿 `commit_id`
  2. **先删该 commit_id 的旧 definitions**（重复索引幂等）
  3. 批量插入
  4. **修剪**：保留集 = `git rev-list -n D <默认分支>`（用现有 `rg_git` 的 rev-list 能力，先查有没有；没有就用 `git` CLI 网关——**不要新写 git 解析**），删掉不在保留集的 `symbol_commits`（级联删 definitions）
- 返回 `IndexReport { commit_id, definitions_written, pruned_commits }`

`D` 的计算：需要单 commit 字节数。**简化方案**：先索引，量一次该 commit 的 definitions 行数与估算字节，或直接固定 `D = 6` 并在 plan 说明「动态 D 留后续」。**自己判断哪个更合适，但要在 plan 说明。**

### 4. 端点

`POST /ai/repos/{o}/{r}/index`（**先查现有路由前缀是否真是 `/ai`，不要凭文档猜**）：
- 入参：`{ commit_sha?: string }`，缺省 = 默认分支 HEAD
- 权限：**需要写权限**（`can_write_repo`），索引是贵重写入操作
- 返回 `IndexReport`

如果 `/ai` 前缀的路由在别处注册，跟着现有模式走；**不要新开路由前缀**。
