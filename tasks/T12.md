## 要求

### 1. 表 + 迁移

`notification_preferences`（窄表）：

| 列 | 说明 |
|---|---|
| `id` | 自增 |
| `user_id` | 谁 |
| `repo_id` | `NULL` = 全局默认，非空 = 该仓库覆盖 |
| `event_type` | 事件类型（与 `notifications.event_type` 同集合） |
| `channel` | `in_app` / `email` |
| `enabled` | bool |
| `updated_at` | |

唯一键 `(user_id, repo_id, event_type, channel)`。迁移 `m20261115_000002_create_notification_preferences.rs`，`Migrator::down` **29 → 30**。

**语义**：表里没有记录 = 该渠道**开启**（默认订阅）。只有显式写入 `enabled = false` 才是关闭。这样不需要为每个新用户初始化一堆行。

### 2. 单一出口

新建 `crates/rg-core/src/notification/dispatch.rs`：

```rust
pub struct NotifyRequest {
    pub recipients: Vec<i64>,       // user_id
    pub event_type: String,
    pub repo_id: Option<i64>,
    pub title: String,
    pub body: Option<String>,
    pub action_url: Option<String>, // 邮件里的跳转链接
}

pub async fn dispatch(db: &DatabaseConnection, mailer: Option<&Mailer>, req: NotifyRequest) -> DispatchOutcome
```

`dispatch` 内部对每个 recipient：

1. 查偏好（先取该 repo 的覆盖，没有则取全局 `repo_id IS NULL`，再没有则默认开启）
2. `in_app` 开启 → 写 `notifications` 行
3. `email` 开启且收件人有邮箱且 `mailer.is_some()` → 发邮件
4. 结果汇总成 `DispatchOutcome { in_app: usize, email: usize, skipped_by_preference: usize, failed: usize }`

**关键**：邮件发送失败**不能**让通知整体失败（in_app 已经写入）。失败只记 warn 并计入 `failed`。

### 3. 收敛现有调用点

把 13 处 `notification::notify(...)` 与 3 处 `email::send_html_notification(...)` 改成走 `dispatch`。

- **只换入口，不改语义**：原来发给谁、什么 event_type、什么标题正文，必须一模一样。
- 邮件原本在 `lib.rs` 里是「查到收件人 → 发信」，改成「构造 NotifyRequest → dispatch」，**不要顺手改邮件模板或正文**。
- 如果某处调用点所在的函数没有 `mailer`，允许传 `None`（此时只写 in_app）。**不要**为了传 mailer 去改函数签名链——那会扩散改动面，plan 里说明即可。

### 4. 端点（两个）

- `GET /user/notification-preferences` — 列当前用户的有效偏好（含未显式设置时的默认值推导）
- `PUT /user/notification-preferences` — 批量 upsert（body 形如 `[{repo_id, event_type, channel, enabled}]`）

路由三处齐（`lib.rs` / `openapi.rs` / `route_meta.rs`）。
