## Task Constraint

复核阶段登记的 **R19-1（P1）**：合并审批的准入面。

现状（`api/reviews.rs:312`）：`submit_review` 只过 `require_authenticated_read` ⇒ **能读这个仓库的人就能投 approve**。而合并门（`branch_protection/service.rs:457`）只数 human approvals。

后果：公开仓库上，任何登录用户都能给任何一个 PR 投批准票。私有仓库影响面小，公开仓库等于没有审批。

## 决策（已定，不要再纠结）

**收紧到「写权限」**（`repo::service::can_write_repo`），不引入显式审批人名单。

理由：现有仓库没有配置审批人名单，引入名单等于「全部不能批」，那是另一个维度的破坏。写权限是合理的最小门槛——能推代码的人才该给别人代码背书。

## 只收紧 `approve`，不动其它动作

| action | 准入 | 理由 |
|---|---|---|
| `approve` | **写权限**（`can_write_repo`） | 唯一进合并门计数的动作，是「给合并背书」 |
| `request_changes` | 保持 `require_authenticated_read` | 任何人（含外部贡献者）都应能表达「这里有问题」，它不是批准 |
| `comment` / 其它 | 保持 `require_authenticated_read` | 同上 |

**不要顺手把 `request_changes` 一起收紧**——那会让外部贡献者无法提出反对意见，是权限误伤。

## 实现

`submit_review` 已通过 `require_authenticated_read` 拿到 `(repo_model, user_id)`，所以直接用：

```rust
if action.as_str() == "approve" {
    match rg_core::repo::service::can_write_repo(&state.db, &repo_model, Some(user_id)).await {
        Ok(true) => {}
        Ok(false) => return AppError::forbidden(
            "only users with write access to this repository can approve a pull request"
        ).into_response(),
        Err(e) => return AppError::from(e).into_response(),
    }
}
```

位置：在 `ReviewAction::parse_action` 之后、现有的自批检查之前或之后都行，但**必须在写库之前**。自己选位置并在 plan 说明。

`AppError::forbidden` 若不存在，用现有的等价构造（先读 `error.rs` 确认，不要新造一个）。

## 验证

1. **只读者不能 approve**：collaborator 为 `read` → 403，且 `pr_reviews` 无新行、`count_current_human_approvals` 不变
2. **只读者仍能 comment 与 request_changes**：同样身份 → 成功（证明没误伤）
3. **写者能 approve**：collaborator `write` → 成功
4. **owner 能 approve 自己的仓库**：owner 身份 → 成功（`can_write_repo` 对 owner 恒 true）
5. **非成员不能 approve**：完全无关用户 → 403
6. **agent 行为不变**：agent 的 approve 仍走原有 `AGENT_MAY_NOT_APPROVE`（若已有），本任务不改变 agent 路径
