# Task T18 - [#15 第六步] `pr.opened` 加事务 + `pr.closed` 修正事件顺序

> 本文件是该任务状态的唯一权威；`TASKS.md` 只放镜像索引。

## Task Constraint

前四步搬的都是「事件在业务写之后」。本任务里有**一条事件在业务写之前**，那是个真缺陷，不只是缺少事务。

### 已核实的现状（`6275d67` 时点）

**① `pr.opened`**（`create_pr`，`pull_request/service.rs:122`）：
单条 insert + `pr_event_ops::record`，**无事务**；事件在 insert 之后（顺序正确，只缺事务）。

**② `pr.closed`**（`update_pr`，`:354`）——**顺序是错的**：

```
:406-427  if was_open && s == "closed" {
              ... trigger_pr_closed(db, ...)        // ← 先发 webhook
          }
:456      let updated = pull_request_ops::update(db, active).await?;   // ← 后写库
```

**webhook 在 DB 更新之前发出。** 如果 `update` 失败，消费者已经收到「PR 已关闭」，实际状态没变。这比「提交后写事件」更严重：前者会丢事件，后者会**发出不存在的事实**。

**③ `milestone.closed`** —— **本任务不改**。`notify_milestone_closed`（`issue/service.rs:485`）是纯通知函数，没有业务写；它被 `update_issue` 的 fail-soft 块调用（`:339` `if let Err(e) = ... { warn }`）。事务里只剩事件写，没有需要一起提交的业务变更，改了只是加开销。**不要碰它，也不要碰 `issue/service.rs`。**

## 要求

### 1. `pr.opened`：加事务（模式同 T17）

```rust
let txn = db.begin().await?;
let pr = pull_request_ops::create(&txn, model).await?;     // 若签名未放宽，一并放宽
pr_event_ops::record(&txn, ...).await?;                    // 原本就在 insert 之后
let payload = json!({ /* 9 字段逐字节不变 */ });
let event_payload = json!({ "event": "pull_request.opened", "pull_request": payload });
record_event_in_txn(&txn, repo_id, "pull_request.opened", &event_payload).await?;
txn.commit().await?;
if let Err(e) = deliver_event(&db, repo_id, "pull_request.opened", &event_payload).await { warn }
```

`create_pr` 前面的校验（base/head 分支存在、重复 PR 检查等）**全部留在事务外**。

### 2. `pr.closed`：修正顺序 + 加事务（本任务的重点）

```rust
// 状态变更只改内存里的 pr（:400-418 那段），不要在这里发事件
if let Some(s) = &state { ... pr.state = s.clone(); ... }

// 构造 ActiveModel（现有代码）
...
let txn = db.begin().await?;
let updated = pull_request_ops::update(&txn, active).await?;
// pr_event_ops::record 若原本紧随其后，一并改到 &txn

if was_open && updated.state == "closed" {
    let close_payload = json!({ id, repo_id, number, title, state });   // 5 字段逐字节不变
    let event_payload = json!({ "event": "pull_request.closed", "pull_request": close_payload });
    record_event_in_txn(&txn, updated.repo_id, "pull_request.closed", &event_payload).await?;
}
txn.commit().await?;

if was_open && updated.state == "closed" {
    if let Err(e) = deliver_event(&db, updated.repo_id, "pull_request.closed", &event_payload_saved).await { warn }
}
```

要点：
- **事件必须在 `update` 之后**。这是本步的核心，不只是加事务。
- `was_open` 在状态变更前算，需要在函数作用域内保留到事件块（可能要把 `let was_open` 提到 `if let Some(s)` 外面）。
- 如果 `state` 不是 `closed`（比如只改 title），**不写也不投递** `pull_request.closed`。
- `trigger_pr_closed` 改写后若无调用点 → **删除** + 原位留注释（同 T16/T17 先例）。若还有别处调用 → 保留 + 注释 + 报告说明。

### 3. payload 等价

`pr.opened` 9 字段：`id / repo_id / number / title / state / head_branch / base_branch / head_repo_id / author_id`。
`pr.closed` 5 字段：`id / repo_id / number / title / state`。
字段集合、顺序、值都不许变；外层都是 `{ event, pull_request }` 两键。

## 验证

1. **`pr.opened`**：`repo_events` 恰 1 行、receiver 收到 1 次、9 字段与 DB 行一致。
2. **`pr.closed` 顺序修正（关键断言）**：构造「状态更新失败」的场景，断言 **webhook 没有发出去**。这是本任务唯一能证明顺序被修正的测试——如果只测「正常关闭时收到了事件」，改前改后都通过，等于没测。若确实无法注入 update 失败，**如实说明**并至少断言「事件写入的 `id` 大于 `pr_events` 记录」或其它能区分先后的证据。
3. **`pr.closed` 不误发**：只改 title（state 不变）时，不写 `pull_request.closed`、不投递。
4. **不重复写**：两条路径各断言恰 1 行。建议对 `pr.closed` 做变异测试（让 `deliver_event` 也 append，确认测试变红）。
5. 既有 PR 测试全绿。
