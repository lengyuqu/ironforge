# Task T01 - [#60] PR 合并写到 `base_branch` 而非仓库 `HEAD`

> 本文件是该任务状态的唯一权威；`TASKS.md` 只放镜像索引。

## Task Constraint

**缺陷**：`merge` 与 `squash` 两种合并策略把**仓库 `HEAD`** 当作 ours，而不是 PR 的 `pr.base_branch`。base 不是默认分支的 PR 会被合进错误的分支（或落到与 `pr.base_branch` 无关的历史上）。

已核实锚点（以 `0523bb2` 为准，行号会漂）：

- `crates/rg-core/src/pull_request/service.rs` 的 `gix_merge_no_ff`（约 :1880）与 `gix_squash_merge`（约 :1911）：两者都 `repo.rev_parse_single("HEAD")` 取 ours。
- 调用方 `do_merge_commit`（约 :1688）/ `do_squash_merge`（约 :1693）只传 `pr.head_branch`，**根本没有把 `pr.base_branch` 传下去**。
- 对照 `do_rebase_merge`（约 :1701）用的是 `rg_git::ops::rebase_merge(repo_path, &pr.base_branch, &pr.head_branch)` —— rebase 策略是**正确**的，可作为参照实现。
- 同一文件的 `merge_from_ref`（约 :1580）走 `gix_merge_no_ff`/`gix_squash_merge`，同样受影响。

**要求**（顺序不可颠倒）：

1. **先复现**：写一个测试，构造非默认分支为 base 的 PR 并合并，断言 `refs/heads/<pr.base_branch>` 前进到合并提交、默认分支 ref **不动**。修复前该测试必须失败，把失败输出原样记进 `docs/plans/T01-plan.md`。
2. **再修**：让 `merge` / `squash` 以 `pr.base_branch` 的 tip 作为 ours（不是 `HEAD`）。`merge_from_ref` 这条 fork 路径同步处理。
3. **不要顺手改**：`merge_gates`、合并前置校验、`update_branch`（那是 #17/PR #59 的成果）、PR head 同步逻辑。
4. 若 `HEAD` 的取值在别处被依赖（例如裸仓 HEAD 指向别的分支），在 plan 里写明并保留兜底，但**默认行为必须按 `base_branch`**。
