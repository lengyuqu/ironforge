## 要做的四件事

### 1. 端点 `GET /ai/repos/{o}/{r}/symbols`

查询参数（**两个至少给一个**）：
- `name`：符号名。**精确匹配优先，前缀匹配补充**
- `path`：按文件列定义
- `ref` 或 `commit_sha`：可选，缺省 = 默认分支 HEAD
- `limit`：默认 50，上限 200

返回：

```json
{
  "commit_sha": "abc123",
  "partial": false,
  "limitations": [],
  "items": [
    {
      "name": "index_commit",
      "kind": "function",
      "path": "crates/rg-core/src/search/symbol_indexer.rs",
      "start_line": 120,
      "end_line": 168,
      "signature": "pub async fn index_commit(db: &DatabaseConnection, repo_id: i64, commit_sha: &str) -> Result<IndexReport>",
      "confidence": "exact"
    }
  ]
}
```

**`confidence` 的语义（必须写进文档和代码注释）**：
- `exact`：`name` 与查询词**完全相同**
- `name_match`：**前缀匹配**命中（比如查 `get_` 命中 `get_user`）

这是「这条结果和你要找的是不是同一个东西」的诚实表达，不是装饰字段。

### 2. 缺索引时的行为（死线）

`symbol_commits` 里没有该 commit 的记录 → **404 `SYMBOLS_NOT_INDEXED`**，响应体提示先调 `POST /ai/repos/{o}/{r}/index`。

**绝对不许回落到默认分支 HEAD**。理由：用户查的是「这个 commit 的定义」，回落到别的 commit 会给出**错的**结果，比报错更糟。这条要在代码注释里写明。

### 3. `partial` + `limitations`（诚实边界）

设计文档 §5 的四语言限制必须体现在响应里：

- `partial: true` 当该 commit 的索引存在**已知不完整**的情况（例如：该 commit 里有 `*.svelte` 文件但只有降级解析、或解析失败的文件数 > 0）
- `limitations`: 字符串数组，例如
  - `"svelte files are parsed only inside <script>"`
  - `"N files failed to parse and are not indexed"`
  - `"Rust macro-generated symbols and dyn Trait dispatch are not resolvable by tree-sitter"`

**如果你拿不到「失败文件数」这类数据（T28 没存），就不要编造**——用静态的、已知为真的限制描述（如 svelte 降级、四语言静态解析边界），并在 plan 说明哪些动态信息 T28 没存所以给不出。

### 4. MCP 工具 `find_definition`

在 `crates/rg-mcp/src/tools/mod.rs`：
- `list_tools` 加一条：`find_definition`，参数 `{ owner, repo, name?, path?, ref?, limit? }`
- `call_tool` 加分支，内部调与 HTTP 端点相同的 core 函数（**不要重复实现查询逻辑**）

core 层加 `crates/rg-core/src/search/symbol_query.rs`：
```rust
pub async fn find_symbols(db, repo_id, commit_sha, name: Option<&str>, path: Option<&str>, limit: usize) -> Result<SymbolPage>
```
HTTP 与 MCP 都调它。

## 验证

1. **精确匹配**：查 `index_commit` → 命中 1 条，`confidence == "exact"`，`path` 正确
2. **前缀匹配**：查 `index_` → 命中多条，`confidence == "name_match"`
3. **按 path**：`path=crates/rg-core/src/search/symbol_indexer.rs` → 返回该文件所有定义（**含 `kind='impl'` 吗？不含**——验证排除生效）

5. **limit**：`limit=5` 返回 ≤5 条；`limit=500` → 400
6. **两者都不给**：`name` 和 `path` 都缺 → 400
7. **`partial`/`limitations`**：响应包含这两个字段，`limitations` 非空（至少有 svelte 降级那条）
8. **MCP 工具**：`find_definition` 在 `list_tools` 里可见，`call_tool` 能返回与 HTTP 端点一致的结果
9. **`kind='impl'` 被排除**：查一个 impl 行里的名字（如 `ActiveModelBehavior`）→ 不返回
