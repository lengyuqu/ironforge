## 修复仓库页 "Invalid Date" 问题（2026-06-19 傍晚）

### 根本原因
`crates/rg-http/src/api/repo_content.rs` 中的 `get_commit_log` 函数：
- 原代码：`let author_date = String::new(); // TODO: extract commit time`
- 返回空字符串 `""`，导致前端 `new Date("")` 解析失败，显示 "Invalid Date"

### 修复方案
从 git commit 的 `author.time` 字段提取时间戳，用 `chrono` 格式化为 RFC 3339 / ISO 8601 字符串：
```rust
let time_str = String::from_utf8_lossy(&author.time).to_string();
let timestamp = time_str.split_whitespace().next().unwrap_or("0").parse::<i64>().unwrap_or(0);
let author_date = chrono::DateTime::<chrono::Utc>::from_timestamp(timestamp, 0)
    .map(|dt| dt.to_rfc3339())
    .unwrap_or_default();
```

### 配置文件修复
`ironforge.toml` 中 `[database]` 部分的 `connect_secs` / `idle_secs` 字段位置错误：
- 错误：放在 `[database]` 下（导致读取为默认值 `0`，数据库连接超时）
- 正确：放在 `[timeouts]` 下（对应 Rust 结构体 `TimeoutConfig` 的 `db_connect_secs` / `db_idle_secs` 字段）
- 验证：服务器启动日志显示 `connect_secs=30 idle_secs=600`

### 验证结果
- API 返回：`"date": "2026-06-18T17:24:37+00:00"`
- JS 解析：`new Date("2026-06-18T17:24:37+00:00")` → `Valid: true`
- 格式化输出：`2026年6月19日`（时区转换正确）
- 测试仓库：`testuser/test-project`（已推送测试提交 `b3e6297`）

## 修复 FTS5 索引更新问题（2026-06-19 深夜）

### 根本原因
SQLite 不允许触发器修改虚拟表（"unsafe use of virtual table"），导致：
1. 数据库插入/更新失败（FTS5 触发器报错）
2. FTS5 索引无法自动更新

### 修复方案

#### 1. 删除所有 FTS5 触发器
```sql
DROP TRIGGER IF EXISTS repos_fts_insert;
DROP TRIGGER IF EXISTS repos_fts_delete;
DROP TRIGGER IF EXISTS repos_fts_update;
DROP TRIGGER IF EXISTS issues_fts_insert;
DROP TRIGGER IF EXISTS issues_fts_delete;
DROP TRIGGER IF EXISTS issues_fts_update;
DROP TRIGGER IF EXISTS wiki_pages_fts_insert;
DROP TRIGGER IF EXISTS wiki_pages_fts_delete;
DROP TRIGGER IF EXISTS wiki_pages_fts_update;
```

#### 2. 应用层手动更新 FTS5 索引

**仓库（repos_fts）**：
- `rg-core/src/repo/service.rs::create_repo_with_opts` - 创建仓库时插入 FTS5 索引
- `rg-core/src/repo/service.rs::delete_repo` - 删除仓库时删除 FTS5 索引

**Issues（issues_fts）**：
- `rg-core/src/issue/service.rs::create_issue` - 创建 issue 时插入 FTS5 索引
- `rg-core/src/issue/service.rs::update_issue` - 更新 issue 时更新 FTS5 索引

**Wiki Pages（wiki_pages_fts）**：
- `rg-core/src/wiki/service.rs::create_page` - 创建 wiki page 时插入 FTS5 索引
- `rg-core/src/wiki/service.rs::update_page` - 更新 wiki page 时更新 FTS5 索引
- `rg-core/src/wiki/service.rs::delete_page` - 删除 wiki page 时删除 FTS5 索引

#### 3. 添加 CLI 命令 `rebuild-fts`
- 文件：`crates/rg-cli/src/main.rs`
- 函数：`rg_db::rebuild_fts_indexes`（在 `crates/rg-db/src/lib.rs` 中定义）
- 用法：`ironforge rebuild-fts --db-url "sqlite://./ironforge.db?mode=rwc"`
- 功能：清空并重新填充所有 FTS5 索引表

### 验证结果
- ✅ 数据库插入/更新成功（无 FTS5 触发器错误）
- ✅ `rebuild-fts` 命令成功运行
- ✅ FTS5 索引正确填充：
  - `repos_fts`: 11 行
  - `issues_fts`: 1 行
  - `wiki_pages_fts`: 0 行

### 技术要点
- FTS5 虚拟表不能通过触发器修改（SQLite 安全限制）
- 必须在应用层（Rust 代码）手动更新 FTS5 索引
- 使用 `INSERT OR REPLACE INTO table(rowid, ...) VALUES (...)` 更新 FTS5 索引
- 使用 `DELETE FROM table WHERE rowid = ?` 删除 FTS5 索引

### 踩坑经验（新增）
21. **SQLite FTS5 触发器限制**: SQLite 不允许触发器修改虚拟表（"unsafe use of virtual table"）。必须在应用层手动更新 FTS5 索引，不能依赖触发器自动同步。
22. **FTS5 索引列名匹配**: `INSERT INTO fts_table(rowid, col1, col2) VALUES (...)` 中的列名必须与 FTS5 表定义匹配（如 `issues_fts` 只有 `title, body` 两列，没有 `labels` 列）。
