## 本地调试：Git Smart HTTP 修复

### 发现的问题
1. **路由兼容性**：Git Smart HTTP 路由注册在 `/git` 前缀下，但 git 客户端请求 `/{owner}/{repo}.git/info/refs`。SPA fallback 兜住请求返回 HTML。
2. **pkt-line 格式**（3处）：`writeln!` 多加 `\n`；长度计算不含 `\n`；`# service=` 裸写未 pkt-line 包裹；空仓库 dummy ref 格式错误。
3. **upload-pack stdin 死锁**：`git pack-objects --all --stdout` stdin 是 `Stdio::piped()` 但未关闭，进程等待 EOF。
4. **duplex 死锁**：HTTP handler 用 `tokio::io::duplex(64KB)` 作输出缓冲区，pack 数据超过 64KB 时 write 阻塞等 read 消费，但 read 在 handler 返回后才执行 → 死锁。
5. **V2 协议流程错误**：POST handler 调用 `handle_v2()` 会先发 capability advertisement，但 Smart HTTP 下 advertisement 已在 info/refs GET 响应中发送。POST 只应处理命令（ls-refs/fetch）。

### 已完成的修复
- `strip_git_suffix()` + 根路由注册（兼容标准 git URL）
- V1/V2 pkt-line 格式修正（`# service=` pkt-line 包裹、payload 长度精确计算）
- 空仓库 dummy ref：`<null SHA> HEAD\0<caps>` 标准格式
- upload-pack stdin EOF：spawn 后立即 `take + drop(stdin)` 关闭管道
- duplex 死锁：并发 spawn reader_task，write/read 不互相阻塞
- V2 HTTP POST：新增 `handle_v2_http()` 函数（跳过 capability advertisement，直接处理命令）
- `git_v2.rs` 同步修复 pkt-line 格式 + 适配 `handle_v2_http`
