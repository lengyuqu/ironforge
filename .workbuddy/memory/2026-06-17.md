### 编译环境配置关键点
1. **MSVC linker**: VS Build Tools 已安装于 `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\`，但 Git Bash 中的 `/usr/bin/link.exe`（Cygwin coreutils）会遮蔽 MSVC 的 link.exe。需手动将 MSVC bin 路径加到 PATH 最前面。
2. **Windows SDK**: 10.0.22621.0 已安装于 `C:\Program Files (x86)\Windows Kits\10\`，需设置 LIB 和 INCLUDE 环境变量。
3. **沙箱限制**: 项目内 `target/` 目录受沙箱限制，导致 `aws-lc-sys` 的 NASM 预编译对象文件复制失败（Permission Denied）。解决方案：将 `CARGO_TARGET_DIR` 指向 Temp 目录 (`C:/Users/Administrator/AppData/Local/Temp/ironforge-target`)。

### P0#1 大文件流式处理 — 已修复 ✅
改动涉及 6 个文件，全 workspace `cargo check` 通过（0 错误）。

#### 核心改动
1. **OCI blob 下载** (`oci.rs:get_blob`): `tokio::fs::read` → `tokio::fs::File` + `ReaderStream` + `StreamBody` 流式发送
2. **OCI 分块上传** (`oci.rs:chunk_upload`): `body: Bytes` → `body: Body`，用 `into_data_stream()` 逐 chunk 写入文件
3. **OCI 完成上传** (`oci.rs:complete_upload`): 同上，且 `finalize_upload` 改为流式读文件+增量 SHA256 哈希
4. **跨仓库挂载** (`oci.rs:handle_mount`): `read_blob`+`store_blob`(两次内存复制) → `copy_blob_file`(hardlink/tokio::fs::copy)
5. **LFS 上传** (`lfs.rs:upload_object`): `body: Bytes` → `body: Body`，流式写 temp 文件后用 `zstd::stream::Encoder` 边读边压缩
6. **LFS 下载** (`lfs.rs:download_object`): 使用 `spawn_blocking` + channel 流式解压 zstd，不阻塞 runtime
7. **OCI Storage 层**: 新增 `copy_blob_file` (hardlink/tokio::fs::copy) 和 `finalize_upload` 流式重写
8. **LFS Service 层**: 新增 `read_object_path` 和 `store_object_from_file`
